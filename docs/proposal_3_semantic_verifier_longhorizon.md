# Proposal 3: Semantic Sentinel — 语义敏感的过程验证器与长程任务闭环恢复

> 类型:系统 + 真机闭环实验(应用价值导向)
> 目标会议:CoRL / RSS / ICRA(系统与真机实验受重视的 venue)
> 依托资产:增强后的 GRM(Proposal 2 的方法或数据微调版)、真机遥操平台与长程任务集、Proposal 1 的评测协议作为离线验收

---

## 1. 一句话故事

**长程任务的崩溃往往始于一次"看起来很成功"的子任务——机械臂流畅地操作了错误的物体。我们把语义增强的过程奖励模型部署为子任务级运行时验证器,在错误传播之前捕捉反事实失败并触发针对性恢复,首次在真机长程任务上量化"语义验证"对端到端成功率的贡献。**

## 2. 动机

### 2.1 现有运行时监控的语义盲区

Sentinel(CoRL 2024)把失败分为 erratic(动作统计可检)与 task progression(需 VLM video QA)两类;但其 VLM 通道用通用模型 zero-shot 问答,对"错误物体上的顺利执行"分辨力弱(Guardian 混淆矩阵:wrong-object 类最易被判 success;RACER 也承认其 VLM supervisor 会幻觉误判)。SAFE(NeurIPS 2025)从 VLA 内部特征回归失败概率,擅长捕捉 OOD/execution 异常,但语义错位轨迹恰恰**不是** OOD——它在训练分布内、动作完全正常,内部特征上与成功轨迹高度相似。

结论:现有监控栈存在一个结构性缺口——**没有一个对 instruction-object 对齐敏感的进度信号源**。

### 2.2 为什么是"过程"验证器而非"终局"检测器

- 终局才发现错物体,恢复代价最大(可能需要完整逆操作,甚至不可逆——错误物体已被移动/损坏);
- 过程奖励模型(GRM)天然输出逐段进度增量,语义增强后可在**抓取瞬间**(margin 骤降)即报警,把恢复成本降到最低;
- skill chaining 文献(Adversarial Skill Chaining, SCaR)证明子任务终态偏差会沿链条级联;子任务边界是验证的最优插入点。

## 3. 系统设计:Semantic Sentinel

三层验证-恢复架构,部署于长程任务执行器(VLA 或 skill pipeline)之上:

### 3.1 信号层:双通道过程验证

- **物理通道**:GRM 原生进度增量(捕捉掉落、停滞、倒退——进度骤降/为负);
- **语义通道**:反事实 margin 信号 `m_t = V(o_t, l_true) − max_j V(o_t, l_cf^j)`,其中 l_cf^j 为场景内其他候选物体的自动改写指令(由场景检测或任务规划器提供候选集);语义增强(head steering)保证该 margin 可分。m_t 骤降或为负 ⇒ 疑似操作了错误物体。
- 两通道以 Sentinel 式"或"逻辑并联,各自用 conformal prediction(借鉴 SAFE)在校准集上定阈值,给出误报率保证。

### 3.2 决策层:子任务级仲裁

在子任务边界(gripper 开合、keyframe)强制校验;子任务内按低频率巡检(语义通道计算量大,只在关键帧触发)。报警后仲裁器输出结构化诊断:失败类型(物理/语义)、置信度、疑似实际操作物体(取 argmax V(o_t, l_cf^j) 的 j——语义通道免费附赠的归因能力)。

### 3.3 恢复层:类型条件化恢复策略

- 物理失败 → 重试当前子任务(retry);
- 语义失败(错物体、未完成交互)→ 中止 + 直接重新执行正确指令;
- 语义失败(错物体、已改变场景)→ 生成逆操作子任务(put it back)后重规划——诊断中的"疑似实际物体"使逆操作指令可自动合成,这是通用 VLM 监控器给不出的;
- 恢复由上层 planner(LLM 或固定脚本)执行,系统与具体 policy 解耦(可套用在任意 VLA 上,对齐 DoReMi/RACER 的外挂 supervisor 范式)。

## 4. 实验设计

### 4.1 平台与任务

真机双臂/单臂平台,3-5 个长程任务(每个 4-8 子任务),场景含多个同类干扰物(制造反事实失败的温床);执行 policy 选一个公开 VLA(已知有指令失明问题,保证自然产生 wrong-object rollout)+ 注入式扰动(在部分 trial 中故意换指令)保证失败样本量。

### 4.2 对照组

| 系统 | 说明 |
|------|------|
| No monitor | 裸 policy,失败自然级联 |
| Sentinel-style | STAC 型动作一致性 + 通用 VLM (GPT-5/Gemini) video QA |
| SAFE-style | policy 内部特征失败检测器 |
| GRM 原生 | 未增强 GRM 进度骤降报警(只有物理通道) |
| Ours (full) | 双通道 + 类型条件化恢复 |
| Ours 消融 | 去语义通道 / 去类型条件化(全部 retry)/ 去 head steering |

### 4.3 指标

- **检测**:wrong-object 失败的召回/精度、检测延迟(距错误抓取的秒数/子任务数)、误报导致的无效中断率;
- **端到端**:长程任务成功率、平均完成时间、恢复成功率(报警后最终完成任务的比例);
- **归因质量**:疑似实际物体的 top-1 准确率(支撑逆操作恢复);
- **离线验收**:信号层在 CF-GRM-Bench(Proposal 1)上的 AUROC 作为部署前标定。

### 4.4 分析实验

- 检测延迟-恢复成本曲线:证明"过程级早发现"相对"终局检测"的恢复成本优势(语义失败被越早发现,逆操作越简单);
- 级联分析:统计 no-monitor 组中一次 wrong-object 错误平均污染多少后续子任务,量化问题的"致命性"(直接支撑论文动机);
- 误报剖析:hard positive(同义指令)与视角变化下的稳定性。

## 5. 贡献点

1. **C1(系统)**:首个以语义敏感过程奖励模型为核心的长程任务运行时验证-恢复框架,补上现有监控栈(动作统计 / 内部特征 / 通用 VLM QA)对反事实失败的结构性盲区;
2. **C2(机制)**:反事实 margin 作为运行时语义信号的设计与 conformal 校准,附带"疑似实际物体"归因能力,使**自动逆操作恢复**成为可能;
3. **C3(实证)**:真机长程任务上的首次量化:语义验证对端到端成功率/恢复成本的贡献,以及 wrong-object 错误级联效应的测量;
4. **C4(即插即用)**:验证器与 policy 解耦,可外挂于任意 VLA/skill pipeline。

## 6. 风险与备选

- **风险 1:真机长程实验工程量大、方差高** → 分两级:仿真(LIBERO-Long / RoboCasa 长程套件 + 注入反事实指令)先出全量对照,真机只跑核心对照(No monitor / Sentinel-style / Ours);
- **风险 2:语义通道推理延迟影响实时性** → 只在子任务边界与关键帧触发;GRM-4B 轻量版;异步执行(报警滞后 1-2 秒在操作任务中可接受,且仍远早于终局);
- **风险 3:候选反事实指令集构造依赖检测器** → 用开放词汇检测(GroundingDINO,仓库已有相关脚本)自动枚举场景物体;检测失败时退化为 l_null 对照(margin 相对空指令),牺牲归因保检测;
- **风险 4:恢复策略被质疑简单** → 恢复不是本文贡献核心,采用固定脚本 + LLM 重规划的成熟范式(DoReMi/RACER);贡献在"检测得早、诊断得准使恢复变得可能"。
