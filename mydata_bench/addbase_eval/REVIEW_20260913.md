A 仓库的 Robometer 主评估链路，以及修正后的 `sole_official_v2`，通过了本轮源码对照、
35 项 CPU 回归检查和真实权重小样本执行核验，可以用于后续冻结协议下的实验。

SOLE 历史 `sole_official` 结果仍不能作为修正版的结果，必须重新生成 baseline、ranking、steering。

这里的可靠性指输入、读出、干预、递推和评分符合声明的实验协议，不表示 SOLE 性能已经变好，
也不是对所有硬件、任意新配置或全部探索性模块的无条件保证。

Material Passport：本地代码/原始预测；验证对象为 `addbase_eval` 主链路及其
`meter_eval`、`top_eval` 入口；A 为 Robo-Dopamine，B 为 Robo-Dopamine-addbase。
Verification Status：源码与历史指标 ANALYZED；下列 35 项测试及列明的小样本执行 VERIFIED；

- Robometer：`robometer/data/collators/rbm_heads.py`、`models/rbm.py`、`models/heads.py`、`models/utils.py`。
- RewardGen / SOLE：`rewardgen/sole.py`。

官方来源：[Robometer](https://github.com/robometer/robometer)、
[RewardGen](https://github.com/Philip-MIT/rewardgen)。
两仓库的本地 collator、RBM 模型、SOLE 参考源码也相同。
网络读取状态和哈希见
[upstream_sources_verified_20260913.json](../../results/mydata_bench/experiments_v2_addbase/research/upstream_sources_verified_20260913.json)。

| 核对环节 | A 当前行为与结论 |
| --- | --- |
| Robometer 输入 | 官方 multi-image collator 不调用 480 缩放分支；冻结数据为 640×480，300 visual keys/帧。用官方 collator 的原函数独立构造输入，含左 padding 的文本、ID、grid、像素张量全部一致 |
| Robometer 权重和 head | 严格加载 738 个张量，无 missing/unexpected keys；最后 prog token 的 10-bin progress head 和 success head 与官方 head 原函数一致 |
| Robometer 概率计算 | progress 对已知 logits 始终做 float32 softmax；success 在 float32 做 sigmoid。后者与官方服务的 bf16 sigmoid 存在舍入差别，详见下文 |
| SOLE 输入 | 官方 external-only 首/前/当前拼图，factor-28 PIL resize 后由原生 processor resize；不再手工替代第二次 resize |
| SOLE 递推 | 七步，每个条件从字符串 `0` 开始，反馈自身上一步绝对百分比字符串；ranking 使用 baseline 第六步作为末步前驱 |
| SOLE 解码和解析 | 明确 greedy、512 新 token；这是本实验的确定性配置。严格解析一个完整数值 answer，异常输出记无效，越界百分比裁剪至 [-100,100]；不声称复刻官方宽松解析或 vLLM 随机采样分布 |
| Attention | bias 加在 softmax 前，仅作用于选定 head 的视觉 key；保留 causal/padding mask；新生成文本 key 的 bias 为 0；ranking pass 不修改随后 baseline |
| 映射与时域 | video tubelet 取两源帧 bbox 的包围并集；SOLE last_frame 是每步当前图块，七步均干预。拼图边界 visual cell 可混合相邻图块或黑边，不能解释为严格像素隔离 |
| 评分 | label 仅用于离线 join；严格端点为 suc ≥0.875 / fail ≤0.125；五档 MAE 与端点准确率分别计算；无效输出不算预测正确，固定分母和有效分母均有记录 |

## 本轮新增修复

| 文件 | 发现的边界问题 | 修复 |
| --- | --- | --- |
| `top_eval/protocol.py` | 只数“数值 answer”，可能接受 `<answer>bad</answer><answer>50%</answer>` | 同时核验标签数与完整数值内容，混合、多重、嵌套或不完整标签拒绝 |
| `meter_eval/model.py`、`addbase_eval/score.py` | 未拦截非有限 logits；`status=ok` 的 NaN 可能被五档函数映射为最低档 | head 层拦截非有限值；summary、配对比较、matched controls 统一检查有限数值，不将其计为正确失败 |
| `addbase_eval/runtime.py` | `zip(samples, previous)` 可静默截断不等长输入 | 显式检查批次长度与八帧约束 |
| `addbase_eval/run.py` | ranking 缓存数量相同、ID 不同时，仅检查数量可能放过错误发现集 | 拒绝发现集之外的缓存 ID |
| `addbase_eval/score.py` | 自定义 inputs 可能误用默认评分 population；预测文件可能混入其他 condition | 核验运行 manifest、condition 一致性、预测 ID 所属 population |

这些是实际可构造的错误输入/缓存边界，已加针对性测试。扫描历史冻结矩阵的
197,292 条最新预测后，没有发现非有限有效输出，也没有旧有效 SOLE 输出会被新增标签校验拒绝。
因此这些新增修复不改变已发布 Robometer 指标。上一轮 SOLE 图像处理和反馈修复则确实改变模型输入，
不能沿用历史官方输入结果。

## 真实权重执行结果

环境：A100 80GB，PyTorch 2.8.0+cu128，Transformers 4.57.0。
核验样本为冻结发现集最前两条：`suc/ljx_lfz_task_1_1/1`、`suc/ljx_lfz_task_1_1/2`。

Robometer：官方输入张量逐元素相等；同一 hidden state 上官方 head 的 float32 读出逐元素相等；
ranking 和 steering 后普通 baseline 恢复。按历史实际 batch size=4 及相同样本分组运行，
这两条样本的 baseline 和 last-frame k32 的 progress、success 与历史值误差全部为 **0**。
YAML 默认 batch size=1，历史 scheduler 实际使用 4；batch size=1/2 相对旧批次的小样本最大差异
为 progress 0.000630、success 0.000343。因此逐位复现须保持批次和运行环境一致。

SOLE v2：通过生产 `_predict_condition` 跑完整七步 baseline，逐步用独立官方函数构造输入，
直接调用模型 greedy 生成。两样本共 14 次预测的输入张量与输出文本全部一致；
随后重新 ranking、执行七步 last-frame k8，检查 prefill/decode hooks 和自身前驱反馈，最后 baseline 恢复。
这次 ranking 仅含两个核验样本，不能把它的 steering 输出当成正式 34 样本发现集的实验成绩。

## A/B 仍然存在的区别

| 项目 | A | B | 如何解释 |
| --- | --- | --- | --- |
| Robometer 官方输入 | 640×480；300 keys/帧 | 手工最长边缩到 480，再处理成 480×352；165 keys/帧 | B 是自定义缩放配置，不能称严格官方预处理；不是 A 的错误 |
| Robometer progress 读出 | 始终 softmax 已知 logits | `meter_eval/readout.py` 原读出继承官方 `sum==1` 类型猜测 | 该猜测有缺陷，已知 logits 和为 1 也必须 softmax；B 的历史 progress 有两个越界值，success 不受此问题影响 |
| 普通 SOLE 五协议 | 八帧单次终点预测 | 七步递推，视频重复首/前/当前图像 | 是不同实验协议，不能仅凭分数不同判断谁实现错误，也不能把普通 A 配置称官方 SOLE |
| SOLE steering 时间 | 当前图块/全部图块，七步都干预 | 部分配置为 terminal_step，仅最后一步 | 非等价干预；对比必须核对具体配置 |
| 负 bias 范围 | 所选时域的内容区域 | 相关 steering 实现使用全部 visual key | last_frame 的含义及效应不等价 |
| failure 阈值边界 | ≤ low | 相关旧统计为 < low | 恰等于阈值时不同；比较时需统一定义 |

本轮没有修改 B 仓库。B 的相关差异不能作为 A 独立重复验证成功的证据。

## 可靠的已存结果与数值精度

下表均为 **A / Robometer / official input / success head / 原严格端点口径**。

| 条件与 population | n（suc / fail） | 五档 MAE | overall | suc | fail |
| --- | --- | --- | --- | --- | --- |
| 全量 baseline | 1213（407 / 806） | 1.5664 | 47.57% | 83.54% | 29.40% |
| cohort baseline | 846（268 / 578） | 1.2258 | 56.03% | 89.93% | 40.31% |
| cohort last-frame k32 | 846（268 / 578） | 0.5201 | 80.97% | 70.15% | 85.99% |

修复后的评分器已重新评分 Robometer official 的全部 19 个条件。`conditions`、
`secondary_success_head`、`matched_controls` 三部分与历史 `analysis_v1` 的 JSON 内容完全一致，
见 [重新评分产物](../../results/mydata_bench/experiments_v2_addbase/analysis_meter_reaudit_20260913/meter_official.json)。

官方服务对 bf16 success logits 直接 sigmoid，A 在 float32 做 sigmoid，这是数值精度选择，
不是错接 head。把保存的 A 概率舍入至 bf16 的离线敏感性检查得到：全量 strict 47.57%→47.90%，
cohort baseline 56.03%→56.15%，last-frame k32 80.97%→81.09%。这个舍入对照不是官方全模型重跑，
不替换上表。它说明“官方输入、官方 head 结构”不等于“逐位复刻官方服务输出精度”。

统计解释检查 11/11 已逐项考虑：Simpson/分组方向（suc 降、fail 升，不声称各类均改善）；
生态谬误（不推广到每条轨迹）；Berkson/选择偏差（cohort 经 grounding 筛选）；
collider（未做因果调整，不作人群因果推断）；基率（列明 suc/fail 数量）；
回归均值（不把最佳 k 的选择视为独立确认）；幸存者（保留无效输出与固定分母）；
多重搜索（success 表是描述性结果，未补做独立显著性验证）；分析分支（固定原阈值、原 MAE，
不改用二分类准确率替换）；相关因果（仅描述冻结样本上的模型干预效应，不宣称真实机器人成功率提高）；
逆向因果（仅核对算法执行顺序，不建立现实世界因果结论）。
同域 730 条视频组 holdout 与外部验证集不同；本轮不对未测试任务或新数据给出泛化保证。
